# Documented cases of Claude / LLM-driven trading on Polymarket and Kalshi (through 18 Nov 2026)

Research method caveat (read first): in this session direct page fetches were blocked by the network allowlist (vallettasoftware.com, dev.to, stepsecurity.io, crypto.news all failed to resolve; GitHub API access to third-party repos was refused). Everything below therefore comes from web-search result summaries and snippets, not from full-text reads of the pages. URLs are the pages the search engine attributed the facts to. Where I could not tell which of several result URLs carried a figure, I say so. Per-model tables in papers (e.g. Claude's exact row in Prediction Arena) could not be opened. Nothing here was verified on-chain by me; "verifiable on-chain" means the wallet is public and could be checked, not that I checked it.

Classification used throughout:
- (a) LLM as code-writer: Claude wrote a mechanical bot (latency arb, copy trading, market making, weather-model comparison). The edge, if any, is not the LLM's judgement.
- (b) LLM as runtime forecaster/decision-maker: the model estimates probabilities or picks trades while the bot runs.

Evidence ratings: [ON-CHAIN CHECKABLE] wallet/account is public and P&L can be checked, attribution to Claude may still be unproven; [BENCHMARK] run by researchers with a stated method; [SELF-REPORT] plausible but unverified first-person account; [MARKETING] promotional, affiliate, vendor or anonymous viral claim.

## 1. What open-source projects exist for LLM-driven Polymarket/Kalshi trading (official `agents` repo, community repos, MCP servers, Olas/Valory agents), and what live P&L have they published?

### Takeaway
There is plenty of open-source scaffolding (Polymarket's official `agents` framework, several Claude-forecaster repos, at least seven Polymarket MCP servers, the Olas Polystrat/Omenstrat fleet), but I found no open-source LLM-forecaster repo with an audited, positive live P&L. The only fleet with published aggregate numbers (Olas) says through its own builder that it is "not yet at a fleet-wide break even".

### Cited Findings
Official / framework:
- `Polymarket/agents` is the official developer framework "for building AI agents for Polymarket", MIT licensed; README references LangChain and Chroma; it provides RAG, news and web-search data sourcing and Polymarket API integration; a `Chroma.py` connector vectorises news. Class (b) scaffolding. No live P&L is published. — [docsearch mirror of repo](https://docsearch.algolia.com/mcp/docs/repo/polymarket/agents); [sourcepulse listing](https://www.sourcepulse.org/projects/972586)
- A third-party catalogue listed it at 608 stars (undated, probably stale), and an aggregator's last sync was 27 Sep 2025 (a sync date, not a commit date). — [sourcepulse](https://www.sourcepulse.org/projects/972586); [ecosyste.ms](https://awesome.ecosyste.ms/projects/github.com%2FPolymarket%2Fagents)
- Many GitHub repos with the same description (e.g. `VirilePeak/agents`, `denbasta/agents`) are forks/clones of the official repo; treat as unofficial copies. — [VirilePeak/agents](https://github.com/VirilePeak/agents); [denbasta/agents](https://github.com/denbasta/agents)

Community repos where the LLM is the runtime forecaster (class b):
- `datori/market-edge`: "scans Polymarket for mispriced markets, estimates probabilities using a multi-pass Claude pipeline, sizes positions with Kelly criterion, and executes trades or paper-trades against a local portfolio"; default Kelly fraction 0.5. No published live P&L found. — [datori/market-edge](https://github.com/datori/market-edge)
- `pallaoro/polymarket-ai-trading`: paper-trades by default; pulls markets from the public Gamma API, scores market quality, generates mean-reversion signals (longshot bias, favourite-fade), gates each idea through an LLM "risk desk", sizes with Kelly. — [ecosyste.ms listing](https://awesome.ecosyste.ms/projects/github.com%2Fpallaoro%2Fpolymarket-ai-trading)
- `ryanfrigo/kalshi-ai-trading-bot` (Kalshi): third-party sites describe a "five-model ensemble" (Grok, Claude, GPT-4o, Gemini, DeepSeek), but the repo's own current README says it is "not a '5-model ensemble' despite earlier README claims": one model is called per decision, default `anthropic/claude-sonnet-4.5` via OpenRouter; multi-agent voting code is scaffolding not wired into the live path; authors disclaim responsibility for losses. A useful example of README claims outrunning the code. — [ryanfrigo/kalshi-ai-trading-bot](https://github.com/ryanfrigo/kalshi-ai-trading-bot); contradicted by [sourcepulse description](https://www.sourcepulse.org/projects/26594414)
- OpenClaw/ClawHub "polymarket-auto-trader" skill: Claude Haiku as estimator, 5% minimum edge, half-Kelly, 25% position cap; the ClawHub listing is flagged "review recommended". — [ClawHub listing](https://clawhub.ai/polymarket-auto-trader); [getclawkit copy](https://getclawkit.com/skills/official-srikanthbellary-polymarket-auto-trader)
- Other named repos surfaced without detail: `theSchein/pamela`, `better-labs/betteraiengine`, `dingjamma/polybot`, `OpenKrab/ClawPoly`, `al1enjesus/polyclawster`, a `serenorg/seren-skills` "polymarket-bot" agent skill. I could not open them; no P&L evidence. — [pamela](https://github.com/theSchein/pamela); [betteraiengine](https://github.com/better-labs/betteraiengine); [polybot](https://github.com/dingjamma/polybot); [seren skill](https://skills.sh/serenorg/seren-skills/polymarket-bot)

MCP servers (let Claude Desktop / Claude Code query or trade Polymarket):
- Read-only data servers: `mcp-polymarket` on PyPI (Gamma/CLOB/Data APIs, launched via `uvx` from Claude Desktop config) and `polymarket_mcp_server` on PyPI (FastMCP; discovery, wallet reads, public CLOB data). — [mcp-polymarket](https://pypi.org/project/mcp-polymarket/); [polymarket_mcp_server](https://pypi.org/project/polymarket_mcp_server/)
- Trading-capable: `joinQuantish/polymarket-mcp` (self-hosted, 42 tools incl. order placement, wallet intelligence, copy trading, reward discovery); `IQAIcom/mcp-polymarket` (`npx @iqai/mcp-polymarket`); `guangxiangdebizi/polymarket-mcp` (TypeScript); `undiabler/polymarket-mcp` (Docker, "large-scale agentic integrations"); `0x79de/polymarket-mcp` (Rust, data). — [joinQuantish](https://mcpservers.org/servers/joinquantish/polymarket-mcp); [IQAIcom](https://awesome.ecosyste.ms/projects/github.com%2Fiqaicom%2Fmcp-polymarket); [guangxiangdebizi](https://github.com/guangxiangdebizi/polymarket-mcp); [undiabler](https://glama.ai/mcp/servers/@undiabler/polymarket-mcp/blob/baa24cda6c4fca907144091c408db4705d0e74df/README.md)
- No repo explicitly packaged as an official "Claude Code skill for Polymarket" turned up; the skills that exist are third-party (ClawHub, skills.sh). — [skills.sh](https://skills.sh/serenorg/seren-skills/polymarket-bot)

Olas / Valory (largest documented autonomous LLM-agent fleet):
- Omenstrat (Gnosis/Omen) has traded since July 2023; Polystrat launched on Polymarket in February 2026. — [Olas: Introducing Polystrat](https://olas.network/blog/introducing-polystrat-an-autonomous-ai-prediction-agent-on-polymarket); [crypto.news](https://crypto.news/pearl-prediction-markets-and-the-long-tail-of-ai-liquidity/)
- As of the Olas Q1 2026 roundup (3 Apr 2026): "nearly 14,700 trades across 1,750 markets" by Polystrat agents; legacy Mech agents retired. — [Olas Q1 2026 roundup](https://olas.network/blog/olas-q1-2026-roundup)
- Accuracy: Valory's Minarsch is quoted giving Polystrat 56–69% accuracy, and the fleet is "not yet at a fleet-wide break even". — [crypto.news](https://crypto.news/pearl-prediction-markets-and-the-long-tail-of-ai-liquidity/)
- Promotional/secondary figures: ">37%" of Polystrat agents with positive P&L (claimed to be more than double the human rate), best single-trade return 376%, individual agents "up to 100% ROI", "~70% accuracy" with no methodology; Olas Q4 2025 roundup cites up to ~74% accuracy and one agent at 85% month-to-date ROI. These are best-case, not fleet-average, figures. — [Edgen](https://www.edgen.tech/news/post/ai-agents-score-376-return-rewriting-prediction-markets); [pulse.bot](https://www.pulse.bot/crypto/news/ai-agents-are-quietly-rewriting-prediction-market-trading-3449ebe2-0d69-43f7-baa4-491d6d9f13fd); [Olas Q4 2025](https://olas.network/blog/q-4-25)
- Olas publishes a "Predict Benchmark" leaderboard of models/tools by accuracy and cost on historical data. — [Olas Predict Benchmark](https://valory-olas-prediction-leaderboard.hf.space)

### Inferences
- Accuracy of 56–69% says little about profit: buying favourites yields high hit rates and negative returns after spread. The one honest Olas data point is "not yet break-even at fleet level" with >60% of agents not in profit (if 37% positive is right).
- For a builder, the safest reusable pieces are the read-only MCP/data servers and the official `py-clob-client`-style libraries; trading-capable third-party servers and skills carry key-handling risk (see section 8).
- The Kalshi repo's README correction shows that "multi-model ensemble" is frequently a marketing label; check the live code path.

### Gaps
- Could not read GitHub directly: current stars, last-commit dates and open issues for `Polymarket/agents`, `valory-xyz/trader`, `datori/market-edge` etc. are unverified. (From memory, unsourced: Polymarket also released an official CLI in 2026 and `Polymarket/agents` had well over 1k stars; verify before citing.)
- No independent audit of Olas fleet ROI found; per-category accuracy for Polystrat not found.
- No open-source LLM-forecaster repo with a public wallet and sustained positive P&L was found. Absence of evidence, given blocked fetches, is not proof of absence.

What happened to the edges:
- Polymarket added taker-only fees to 15-minute crypto up/down markets around 6 Jan 2026 (documentation change), explicitly linked in coverage to bots exploiting lag between Polymarket prices and exchange spot; fees are redistributed daily in USDC to liquidity providers. — [The Block](https://www.theblock.co/post/384461/polymarket-adds-taker-fees-to-15-minute-crypto-markets-to-fund-liquidity-rebates); [Finance Magnates](https://www.financemagnates.com/cryptocurrency/polymarket-introduces-dynamic-fees-to-curb-latency-arbitrage-in-short-term-crypto-markets/)

- Early data after the rollout: sports volume largely unaffected; crypto a small pullback that may be normal variance. — [Pine Analytics](https://pineanalytics.substack.com/p/polymarket-fee-rollout)

### Inferences
- A $1.73M single win is not arbitrage; sovereign2013 looks like large directional or semi-hedged sports positions. The on-chain P&L may be real while "Claude-powered" is decoration added by the news cycle.
- The 0.072 crypto rate at p = 0.5 is 0.018 per share: 1.8% of the $1 payout notional but 3.6% of the 50c stake. That probably explains the "1.8% vs 3%" conflict and means a taker needs several points of edge per round trip near 50c.
- Viral numbers follow one distribution channel: anonymous X post, then Finbold, then KuCoin/MEXC/BingX flash feeds and Telegram channels. Repetition across those outlets is one source, not corroboration.
- Class (a) edges are speed and infrastructure races that Polymarket has shown it will reprice by rule change. An individual using Claude Code does not have a durable advantage there.

## 3. What have Anthropic or benchmark organisers reported about Claude trading or forecasting on real markets?

### Takeaway
I found no Anthropic-published report of Claude trading prediction markets. Independent benchmarks are consistent: LLMs (Claude included) are near but not above market/superforecaster accuracy as forecasters, and when they trade with real or realistically simulated money most lose; Claude tends to be among the better-calibrated and least-bad, not profitable.

### Cited Findings
- **Prediction Arena** (arXiv 2604.07355, 2026): six frontier models (versions of GPT, Claude, Gemini, Grok, GLM) each traded $10,000 of real capital. On Kalshi all lost over the 57-day study: −16.0% to −30.8%, average −22.6%. On Polymarket the same cohort averaged −1.1%. Best settlement win rate 71.4% (grok-4-20-checkpoint, Polymarket). A second cohort was paper-traded for only 3 days (6–9 Mar; gemini-3.1-pro-preview +6.02%). Stated key finding: initial prediction accuracy is the main determinant, then position sizing on correct predictions. Kalshi used a fixed set of 29 questions; Polymarket was open discovery. [BENCHMARK]. Search summaries give both "57 days" and "Feb 9–Mar 9" for the window, which do not match. — [arXiv 2604.07355](https://arxiv.org/abs/2604.07355); [emergentmind summary](https://www.emergentmind.com/papers/2604.07355)
- **KellyBench** (General Reasoning, April 2026; sports betting over a Premier League season): every frontier model lost money and several went bust. Claude Opus 4.6 was best at launch with about −11% (leaderboard: −11.2% mean ROI over five seeds, worst seed −44.7%, best run −0.2%); GPT-5.4 about −13.6%; Grok 4.20 went bankrupt in one or more runs. The current leaderboard has Claude Opus 4.7 leading at −3.7% mean ROI. Not peer reviewed. [BENCHMARK]. — [Decrypt](https://decrypt.co/364406/ai-beat-sports-betting-market-top-8-models); [General Reasoning](https://www.gr.inc/releases/introducing-kellybench)
- **PolyBench** (arXiv 2604.14199, submitted 3 Apr 2026): 38,666 binary Polymarket markets across 4,997 events with order-book state and news; seven LLMs made 36,165 predictions on market states from 6–12 Feb 2026 with order-book execution simulation. Only two had positive confidence-weighted return (MiMo-V2-Flash 17.6%, Gemini-3-Flash 6.2%); the other five lost while reporting average confidence of 0.808–0.871. [BENCHMARK]. — [arXiv 2604.14199 via RePEc](https://ideas.repec.org/p/arx/papers/2604.14199.html)
- A secondary article on PolyBench-style results says on bets where agents disagreed with the market, three of four lost: Gemini −12%, ChatGPT −14%, Claude −24%. Single unverified member-only article; do not rely on the exact numbers. — [Level Up Coding](https://levelup.gitconnected.com/seven-ai-models-traded-prediction-markets-for-a-week-five-lost-money-111f228c6e6c)
- **Prophet Arena** (U. Chicago; arXiv 2510.17638; ICLR 2026): live unresolved Kalshi/Polymarket events. The market baseline is more accurate close to resolution; LLMs show an advantage at long horizons. Top models' Brier scores sit in a narrow 0.17–0.24 band. A paper summary says Claude excels on calibration while GPT-5 leads on Brier/return. [BENCHMARK]. — [arXiv 2510.17638](https://arxiv.org/abs/2510.17638v1); [paper notes](https://en.papernotes.org/ICLR2026/llm_evaluation/llm-as-a-prophet_understanding_predictive_intelligence_with_prophet_arena/); [Decrypt](https://decrypt.co/336298/ai-now-matches-prediction-markets-in-forecasting-real-events-study-finds)
- **ForecastBench** (Forecasting Research Institute): superforecasters still #1, about 0.017 Brier ahead of the best LLMs; on the Brier Index (primary metric since March 2026) superforecasters 70.6% vs best LLMs 67.9% (CassiAI ensemble with crowd adjustment; Grok 4.20 preview). Claude 3.5 Sonnet scored 0.117 (Oct 2024); a year later the best was 0.102. Claude is not the top LLM. An EA Forum critique ("The copier line") examines what market-question scores measure given that the market price is available to copy. [BENCHMARK]. — [FRI: closing the gap](https://forecastingresearch.substack.com/p/llms-are-closing-the-gap-on-human); [FRI: Brier Index](https://forecastingresearch.substack.com/p/introducing-the-brier-index); [EA Forum](https://forum.effectivealtruism.org/posts/8YuG9EuhyYqaNBt7F/the-copier-line-what-forecastbench-s-market-scores-actually)
- **LiveTradeBench** (arXiv 2511.03628; 21 LLMs, 50 days, 18 Aug–24 Oct 2025; US stocks and Polymarket, simulated): general capability rank did not predict trading results (correlation with LMArena about −0.38 on Polymarket); it omits transaction costs, liquidity and slippage. One secondary source says Claude Sonnet 3.7 topped Polymarket at +20.54%; I could not verify that figure. [BENCHMARK, frictionless]. — [arXiv 2511.03628](https://arxiv.org/html/2511.03628v1)
- **Foresight Arena** (arXiv 2605.00420, 1 May 2026): on-chain benchmark scoring agents against the Polymarket mid-price (Alpha = market Brier − agent Brier); includes claude-opus-4-5 among five agents plus a random baseline. Useful statistic: detecting a true edge of 0.02 at 80% power needs about 350 resolved binary predictions. — [arXiv 2605.00420](https://arxiv.org/html/2605.00420v1)
- **DayTrading.com Kalshi experiment**: models lost on average about 14–16% of starting funds; a survey of 11 "markets" arenas found the median model profitable in only two. Secondary. — [Level Up Coding](https://levelup.gitconnected.com/seven-ai-models-traded-prediction-markets-for-a-week-five-lost-money-111f228c6e6c)
- **Anthropic itself**: no system-card or blog result on prediction-market trading was found. A crypto outlet reports Claude being used to simulate the 2026 World Cup 50,000 times in a prediction contest and notes that without stakes it is hard to tell whether such forecasts beat baseline. — [Crypto Briefing](https://cryptobriefing.com/claude-ai-world-cup-prediction-contest/)

### Inferences
- The consistent pattern (forecast accuracy near market; trading P&L negative) implies the losses come from selection (trading where the model disagrees with a better-informed market), overconfidence and sizing, and frictions, not from gross forecasting incompetence.
- The −22.6% Kalshi vs −1.1% Polymarket gap in Prediction Arena probably reflects market selection and trade frequency more than venue: forced engagement with 29 fixed questions vs free discovery. Being allowed not to trade is valuable.
- Newer Claude models lose less (Opus 4.6 −11.2% to Opus 4.7 −3.7% on KellyBench) but had not crossed zero in any benchmark I could confirm.

### Gaps
- Claude's exact per-model returns in Prediction Arena, Foresight Arena and PolyBench were not retrievable (papers could not be opened).
- No Anthropic primary source located; I cannot rule out forecasting evaluations inside system cards for models released in 2026.
- No Claude result in Metaculus tournaments was surfaced by my searches.

## 4. Documented failures and losses: agents that lost money, were prompt-injected, hallucinated or mis-read rules, were front-run, or bled on fees/spreads

### Takeaway
The best-documented failures are mundane: backtests with 98%+ win rates that lose live, bots buying 99c favourites, paper-to-live execution gaps, tiny bankrolls eaten by minimum sizes, and LLMs that over-read news. I found no documented case of a prompt-injected trading agent losing funds, but the attack surface is demonstrated and key-stealing supply-chain attacks are common (section 8).

### Cited Findings
- **High-probability "bond" buying (class a/b hybrid; May 2026)**: Spencer Morgan (Purpose Investments, 7 May 2026) asked AI to find inefficiencies; a no-money run on live data showed about a 98.8% win rate buying tokens at 97c+ near expiry; live, the account went from $400 to $134 in two weeks (another summary of the same story: lost $176 as the bot "bled out over a week"). - **LLM-filtered 5-minute BTC agent**: a live-trading write-up with a post-mortem of paper vs live assumptions; a losing session caused a 93% drawdown (later reduced to 13% after fixes), traced to signal-processing failures. [SELF-REPORT]. — [Medium, gwrx2005](https://medium.com/@gwrx2005/ai-augmented-arbitrage-in-short-duration-prediction-markets-live-trading-analysis-of-polymarkets-8ce1b8c5f362)

[SELF-REPORT]. — [Startup Fortune](https://startupfortune.com/i-actually-gave-an-ai-money-to-trade-on-polymarket-heres-what-nobody-on-twitter-wants-you-to-know/)

Second-hand, on a blog that also publishes promotional bot content; unverified. — [dev.to](https://dev.to/fatherson/the-200k-bot-that-broke-and-how-claude-fable-5-saved-it-polymarket-story-1m8f)
- **Claude Code political-markets agent on Kalshi (Free Systems Substack; part of an academic study)**: uses Haiku to parse each contract's resolution rules; errors "some hilarious, some grave": it got very excited about a Tim Cook-steps-down contract; it "often seemed to overinterpret crude news articles without appreciating the broader context"; unclear how well it reasons about probabilities. Suggests trades to a human. Class (b). [SELF-REPORT, researcher]. — [Free Systems](https://freesystems.substack.com/p/can-ai-reason-about-politics-i-built)
- **Overconfidence at scale**: five of seven PolyBench models lost money at average stated confidence 0.81–0.87. — [arXiv 2604.14199 via RePEc](https://ideas.repec.org/p/arx/papers/2604.14199.html)
- **News context can make forecasts worse**: arXiv 2511.18394 (Nov 2025; 392 verifiable questions filtered from ~10,000) reports that adding news shifted models toward momentum-driven wrong calls on financial questions (correct conservative S&P 500 calls reversed). — [arXiv 2511.18394](https://arxiv.org/html/2511.18394v1)
- **Prompt injection**: a Manifold experiment had Claude resolve a market while users flooded comments with manipulation attempts and fake "admin" posts (a later version deliberately left comments unsanitised). A betting-agent security guide ranks prompt injection as the top risk and recommends validating decisions in a separate constrained execution step and sanitising external content. — [Manifold](https://manifold.markets/PowerTrick/will-claude-resolve-this-market-yes); [agentbets guide](https://agentbets.pages.dev/guides/agent-betting-security)
- **Resolution ambiguity**: a Yale paper (arXiv 2605.30802) on LLM oracles over 1,189 resolved questions found unanimous high-confidence multi-agent answers were 97.87% accurate on 47% of questions; the rest needed human arbitration, and a substantial fraction resisted correction by any architecture. — [arXiv 2605.30802](https://arxiv.org/pdf/2605.30802.pdf)
- **Liquidity bounds on arbitrage**: a UCLA study of Polymarket NBA markets (~75M order-book snapshots, 173 games) found executable mispricings exist but are bounded by shallow depth to retail scale. — [arXiv 2605.00864](https://arxiv.org/html/2605.00864v1)

### Inferences
- The recurring failure is a backtest that ignores fills, spread, fees and tail losses. A 98.8% win rate at 97c+ is roughly break-even before costs by construction (one loss wipes out about 33 wins).
- "Teach the bot not to trade" recurs in the honest accounts and matches Prediction Arena's venue gap: abstention is the cheapest risk control.
- An LLM reading market descriptions, comments and scraped news is taking untrusted input. Even without a documented theft via injection, the execution path should not let model text move funds outside hard-coded limits.

### Gaps
- No documented incident of a live trading agent being prompt-injected into a losing trade, and no post-mortem of an LLM hallucinating resolution rules with realised losses, was found. They may exist on X/Reddit, which I could not read.
- No documented front-running case specific to an LLM agent found.

## 5. What architectures do practitioners converge on, and what edge thresholds, filters and cadences do they use?

### Takeaway
The converged class (b) design is: mechanical market filter, then retrieval (news/web), then multi-pass or multi-agent probability estimate, then blend or compare with the market price, then minimum-edge threshold, then fractional Kelly with hard position caps, with paper mode as default and often a human approval step. The research evidence supports using the market price as an input (an ensemble of LLM plus market beats market alone) more than it supports betting against the market on the LLM's say-so.

### Cited Findings
- **Multi-pass estimate + Kelly**: `market-edge` uses a multi-pass Claude pipeline, Kelly fraction 0.5 by default, with a paper-trade mode. — [datori/market-edge](https://github.com/datori/market-edge)
- **Edge threshold and caps**: the ClawHub auto-trader skill uses a 5% minimum edge, half-Kelly and a 25% position cap, with Claude Haiku as estimator. — [getclawkit](https://getclawkit.com/skills/official-srikanthbellary-polymarket-auto-trader)
- **Quant signal first, LLM as veto**: `polymarket-ai-trading` scores market quality, generates longshot-bias/favourite-fade signals mechanically, then gates through an LLM "risk desk" before Kelly sizing; paper by default. — [ecosyste.ms](https://awesome.ecosyste.ms/projects/github.com%2Fpallaoro%2Fpolymarket-ai-trading)
- **RAG over news**: the official `Polymarket/agents` framework is built around Chroma-vectorised news plus web search feeding an LLM. — [docsearch mirror](https://docsearch.algolia.com/mcp/docs/repo/polymarket/agents)
- **Cheap model for rule parsing**: the Free Systems political agent uses Haiku to parse each contract's resolution rules before forecasting. — [Free Systems](https://freesystems.substack.com/p/can-ai-reason-about-politics-i-built)
- **Supervisor reconciliation, not simple averaging; market as prior**: Bridgewater's AIA Forecaster (arXiv 2511.07678, Nov 2025) runs multiple search-equipped forecasting agents, passes them to a supervisor agent that does further search to reconcile disagreements, then applies statistical calibration against LLM biases. On 1,610 prediction-market questions it underperforms market consensus alone, but an ensemble of AIA Forecaster plus market consensus beats consensus alone; it matches superforecasters on ForecastBench (authors' own report). — [arXiv 2511.07678](https://arxiv.org/html/2511.07678v1)
- **Crowd/market adjustment**: one of the best ForecastBench LLM entries is an ensemble with crowd adjustment ("ensemble_2_crowdadj"). — [FRI: Brier Index](https://forecastingresearch.substack.com/p/introducing-the-brier-index)
- **Horizon filter**: Prophet Arena finds markets beat LLMs near resolution while LLMs do relatively better at long horizons. — [arXiv 2510.17638](https://arxiv.org/abs/2510.17638v1)
- **Weather-bot filters (class a template)**: skip thin markets; trade roughly 2–72 hours before resolution; skip buckets already above ~45c; bias-correct model output; map to the exact resolution station. — [X article mirror](https://youmind.com/landing/x-viral-articles/polymarket-weather-trading-bot-blueprint)
- **Sizing matters after accuracy**: Prediction Arena attributes performance first to prediction accuracy, then to position sizing on correct predictions. — [emergentmind summary](https://www.emergentmind.com/papers/2604.07355)
- **Sample size for validation**: about 350 resolved binary predictions are needed to detect a 0.02 Brier edge over the market at 80% power. — [arXiv 2605.00420](https://arxiv.org/html/2605.00420v1)
- **Abstain unless agents agree**: unanimous, high-confidence multi-agent outputs were 97.87% accurate on the 47% of questions where they occurred (resolution task). — [arXiv 2605.30802](https://arxiv.org/pdf/2605.30802.pdf)
- **Security architecture**: validate LLM decisions in a separate constrained execution step; sanitise external content before it reaches the LLM. — [agentbets guide](https://agentbets.pages.dev/guides/agent-betting-security)
- **Kill criteria**: one practitioner fleet pulls a strategy at −35% drawdown or −20% monthly return for two consecutive weeks. — [falsifylab scoreboard](https://falsifylab.substack.com/p/falsifylab-fleet-scoreboard-week-70b)
- **Cost floor for the edge threshold**: taker fee = contracts x rate x p x (1 − p), with most categories charged since 30 Mar 2026 and geopolitics/world events fee-free. — [River Markets](https://www.rivermarkets.com/insights/polymarket-fees.html); [Pine Analytics](https://pineanalytics.substack.com/p/polymarket-fee-rollout)
- **Minimum order**: 5 tokens per CLOB order constrains very small bankrolls. — [Startup Fortune](https://startupfortune.com/i-actually-gave-an-ai-money-to-trade-on-polymarket-heres-what-nobody-on-twitter-wants-you-to-know/)

### Inferences
- The 5% edge / half-Kelly / 25% cap numbers are community defaults with no evidence behind them. Given measured LLM overconfidence (stated 0.81–0.87 while losing), half-Kelly on raw LLM probabilities is aggressive; shrinking the LLM estimate toward the market price before computing edge is the adjustment the AIA and ForecastBench results point to.
- A defensible design for a new builder: trade only where (i) rules parse unambiguously, (ii) time to resolution is days to months rather than hours, (iii) spread plus fee is well under the required edge, (iv) several independent runs agree; log every forecast and score Brier against the market price for a few hundred resolved markets in paper mode before risking money.
- Cadence evidence is thin: class (b) systems run on scan cycles of minutes to hours; nothing suggests an LLM adds value at sub-minute cadence, where latency bots dominate.

### Gaps
- No practitioner published a controlled comparison of edge thresholds, Kelly fractions or ensemble sizes with live P&L.
- Liquidity filters (minimum volume/depth) used by serious practitioners are not documented in what I could retrieve.

## 6. Which market categories do LLMs do relatively better or worse on?

### Takeaway
Evidence by category is weak and mostly indirect. Best-supported: LLMs are relatively better on longer-horizon, text/news-reasoning questions and worse close to resolution, on sports (every model lost on KellyBench) and on short-horizon financial/crypto price questions, where they chase momentum and compete with latency bots. Weather and short crypto are data/latency games in which an LLM at runtime adds little.

### Cited Findings
- Forecasting ability "varies significantly by category"; in financial questions added news pushed models into wrong momentum-driven forecasts; neither model scale nor prompt engineering alone gave robust forecasters. — [arXiv 2511.18394](https://arxiv.org/html/2511.18394v1)
- Long horizon vs short horizon: LLM advantage at long horizons, market advantage near resolution. — [arXiv 2510.17638](https://arxiv.org/abs/2510.17638v1)
- Sports: all frontier models lost over a Premier League season on KellyBench; best was Claude Opus 4.6 at about −11% (later Opus 4.7 −3.7%). — [Decrypt](https://decrypt.co/364406/ai-beat-sports-betting-market-top-8-models); [General Reasoning](https://www.gr.inc/releases/introducing-kellybench)
- Politics: a Claude Code agent over-interpreted crude news and mis-prioritised contracts; its probability reasoning was of unclear quality. — [Free Systems](https://freesystems.substack.com/p/can-ai-reason-about-politics-i-built)
- Short crypto up/down: the documented edge was latency vs exchange spot, now taxed by taker fees (highest category rate). — [The Block](https://www.theblock.co/post/384461/polymarket-adds-taker-fees-to-15-minute-crypto-markets-to-fund-liquidity-rebates); [Pine Analytics](https://pineanalytics.substack.com/p/polymarket-fee-rollout)
- Weather: edge described as lag between scheduled GFS/ECMWF model updates and market prices, with large-city markets arbitraged in seconds and smaller cities slower; daily-temperature markets cleared about $300–400K in 24h volume as of April 2026. — [printmoneylab ep.2](https://www.printmoneylab.com/2026/03/weather-bot-episode-2-gfs-ecmwf-icon-trading-signals.html); [dev.to](https://dev.to/cryptodeploy/how-polymarket-weather-markets-actually-work-50nb)
- Venue/selection effect: same models −22.6% on a fixed Kalshi question set vs −1.1% with open discovery on Polymarket. — [emergentmind summary](https://www.emergentmind.com/papers/2604.07355)
- Cost by category after 30 Mar 2026: crypto most expensive, sports cheaper, geopolitics/world events fee-free. — [Pine Analytics](https://pineanalytics.substack.com/p/polymarket-fee-rollout)

### Inferences
- The least-bad niche for an LLM forecaster is probably longer-dated, lower-attention, text-heavy markets (policy, geopolitics, tech/AI releases, regulatory outcomes) where rule reading and synthesis matter, fees are lowest and speed matters least. This is inference from horizon and cost evidence, not a measured category result.
- Economics data-release markets likely behave like weather (a quantitative nowcast beats an LLM) but I found no evidence either way.

### Gaps
- No category-level table (politics vs sports vs crypto vs culture/"mention" markets vs AI-release markets) for Claude or any LLM was retrievable; the per-category results in arXiv 2511.18394 and Prophet Arena need a full-text read.
- Nothing found on "mention" markets or tech/AI model-release markets specifically.

## 7. Are there reliable aggregate statistics on how AI-agent/bot wallets perform on Polymarket?

### Takeaway
Yes for "bots" broadly, no for "LLM agents" specifically. Bloomberg's April 2026 analysis and academic work agree that most wallets lose and a small bot-like group takes the profits, and that they win through speed and execution, not better forecasting; bot-like wallets were reportedly slightly less accurate than humans.

### Cited Findings
- Bloomberg (about 29 Apr 2026): more than 100,000 Polymarket accounts lost at least $1,000 since January 2025, nearly double the number with comparable gains; of about two million active wallets, nearly half had gains or losses under $10. — [Bloomberg Markets Daily](https://bloomberg.com/news/newsletters/2026-04-29/most-traders-lose-on-polymarket-and-winners-look-like-bots); [KuCoin flash](https://www.kucoin.com/news/flash/100-000-polymarket-accounts-lose-over-1000-since-2025)
- Same analysis as relayed by secondary outlets: 823 active bot-like accounts earned $131M while all other traders collectively lost the same amount (another report: about 800 accounts clearing more than $100,000 each); bot-like wallets were about 5% of wallets and about 75% of volume; humans' accuracy about 55% vs bots' about 52%, with bots profiting from smaller, more frequent, better-executed trades. Bloomberg is paywalled; these details are second-hand. — [KuCoin flash](https://www.kucoin.com/news/flash/most-polymarket-traders-report-losses-while-a-small-group-of-bots-earns-131m); [Newser](https://www.newser.com/story/388532/polymarkets-biggest-winners-arent-human.html)

- Agent share estimates: LayerHub analytics put agent-run wallets above 30% of active Polymarket wallets; a "42% of volume from automated agents" claim is uncorroborated. "Bot" labels are behavioural inference. — [pulse.bot](https://www.pulse.bot/crypto/news/ai-agents-are-quietly-rewriting-prediction-market-trading-3449ebe2-0d69-43f7-baa4-491d6d9f13fd)

### Inferences
- The winners are market makers, arbitrageurs and latency traders. None of these statistics shows that LLM-forecasting wallets as a class are profitable; the only LLM-agent fleet with data (Olas) is below break-even at fleet level.

### Gaps
- No study isolates LLM-driven wallets from mechanical bots.
- No reliable November 2026 figure for bot share of volume; the 5%/75% figure is from April 2026 secondary coverage.

## 8. Known scams around "Polymarket bots" to avoid

### Takeaway
The "Polymarket trading bot" niche is one of the most heavily targeted for wallet-key theft: malicious GitHub repos and npm packages, poisoned agent skills, hacked custodial Telegram bots, and X-to-Telegram drainer funnels are all documented in 2025–2026. Assume any downloaded bot that asks for a private key in `.env` is hostile until audited.

### Cited Findings
- **Dec 2025, GitHub copy-trading bot**: `polymarket-copy-trading-bot` read users' private keys from `.env` and sent them to an attacker server via a hidden dependency (`excluder-mcp-package@1.0.4`). — [KuCoin flash citing Odaily](https://www.kucoin.com/news/flash/polymarket-copy-trading-bot-project-found-to-contain-malicious-code-stealing-private-keys)
- **Hijacked GitHub org**: attackers created 20+ malicious Polymarket bot repos (e.g. `dev-protocol/polymarket-copytrading-bot-sport`) under the hijacked `dev-protocol` organisation, stealing keys via typosquatted npm packages; star counts were inflated by bot accounts and victims' warning issues were deleted. Advice: assume any key in `.env` is compromised and move funds to a new wallet. — [StepSecurity](https://www.stepsecurity.io/blog/malicious-polymarket-bot-hides-in-hijacked-dev-protocol-github-org-and-steals-wallet-keys)
- **Fake npm CLI packages (2026)**: nine packages published within 30 seconds by the throwaway account `polymarketdev` impersonated Polymarket trading CLIs, linked to `texsellix/polymarket-trading-bot`, and exfiltrated raw Ethereum/Polygon keys; tracked as OSV MAL-2026-4209 to -4216. — [SafeDep](https://safedep.io/malicious-polymarket-npm-crypto-wallet-drainer/); [OSV MAL-2026-4209](https://osv.dev/vulnerability/MAL-2026-4209)
- **Fake arbitrage bot (flagged by SlowMist on 1 Jul 2026)**: malware hidden in a dependency `clob-client-math`; 30 malicious npm packages downloaded by at least 53 developers; one outlet attributes it to DPRK actors and reports an SSH backdoor (attribution not independently confirmed). — [MEXC news](https://www.mexc.com/news/1187684); [Securitricks](https://securitricks.com/attackreports/polymarket-trader-funds-at-risk-dprk-npm-package-steals-wallet-keys-and-installs-ssh-backdoor)
- **General warning**: a developer post titled "Why almost every Polymarket trading bot on GitHub is malicious". — [dev.to](https://dev.to/nevosaynevo/why-almost-every-polymarket-trading-bot-on-github-is-malicious-28o7)

### Inferences
- Practical rules that follow: write the bot yourself (with Claude Code) on top of the official client libraries only; pin and read every dependency; never install third-party "polymarket" skills, MCP servers or npm/PyPI packages on a machine holding keys without reading the code; use a dedicated low-balance wallet; prefer read-only MCP servers; never give keys to a custodial Telegram bot; treat GitHub stars as forgeable.
- An LLM agent with shell access is itself a supply-chain risk: a poisoned skill or README can instruct it to install a malicious package. Keep signing in a separate process with hard limits.

### Gaps
- No victim counts or total losses from the GitHub/npm campaigns were found.
- No documented prosecution or takedown of paid "Claude Polymarket bot" sellers found; evidence on paid-bot sellers is anecdotal.
